# 학급관리 웹앱 설계

(«출결·서류 관리» 로 시작해 2026-10 에 «학급관리» 로 이름을 바꿨다. 아래 출결 부분은 그때 설계 그대로다.)

담임교사가 학급 학생의 출결 상황과 증빙서류 수합을 한 곳에서 관리하는 웹앱. 기준 학교: 원묵중학교.

## 사용자·운영 방식

- 사용자: 담임교사 1인 (학생·학부모는 사용하지 않음)
- 서류는 종이로 받고, 앱에서는 **받았는지 여부만 체크**한다 (파일 업로드 없음).
- 데이터는 교사 브라우저의 IndexedDB 에만 저장한다. 외부 서버로 전송하지 않는다.
  - 다른 기기로 옮기거나 브라우저 데이터를 지울 때를 대비해 **백업 파일(JSON) 저장·불러오기**를 제공한다.
  - 마지막 백업 후 7일이 지나면 상단에 알림을 띄운다.

## 출결 분류

- 상황: 결석 · 지각 · 조퇴 · 결과
- 종류: 출석인정 · 질병 · 미인정 · 기타
- 출석인정 세부 사유: 법정감염병 · 체험학습 · 경조사 · 생리 · 공문
- 결석은 기간(시작~종료)으로 입력하고, 결석일수는 **수업일**(토·일요일, 공휴일, 재량휴업일 제외)만 센다.
- 결과는 해당 교시를 기록한다.
- 기타 결석: 학교장이 인정하는 부모·가족 봉양, 가사 조력, 간병 등 (드묾)

## 상세 사유

모든 출결 입력에 상세 사유(예: 감기, 생리통)를 반드시 입력한다. 체험학습은 예외(사유가 곧 체험학습). 첫 화면 출결 현황의 괄호 안에 표시된다.

## 필요서류 자동 생성

| 기록 | 결석계 | 증빙 |
|---|---|---|
| 출석인정 (결석·지각·조퇴·결과) | 필수 (체험학습 제외) | 사유별 (아래) |
| 질병 결석 | 필수 | 진료확인서 등 (필수) |
| 질병 지각·조퇴·결과 | 없음 | 진료확인서 등 (선택, 담임 재량) |
| 미인정 · 기타 | 없음 | 없음 |

출석인정 사유별 증빙:

| 사유 | 증빙 |
|---|---|
| 법정감염병 (독감, 코로나19, 백일해 등) | 의사 소견서 |
| 체험학습 | 체험학습 신청서, 체험학습 보고서(사진 등 첨부) |
| 경조사 (결혼, 입양, 사망 등) | 청첩장·사망진단서 등 |
| 생리 | 없음 |
| 공문 (대회 참가 등) | 공문 |

- 각 서류의 필수/선택은 기록마다 바꿀 수 있고, 서류를 직접 추가할 수도 있다.
- 출결 종류를 바꾸면 서류 목록을 다시 만들되, 이미 받은 서류 상태는 유지한다.

## 규칙 검사 (경고만, 자동 변경 없음)

규칙에 어긋나도 앱은 기록을 바꾸지 않고 경고만 띄운다. 판단은 담임이 한다.

- **생리**: 지각·조퇴·결과·결석을 통틀어 **달력 월 기준 월 1회**. 같은 달 두 번째 기록부터 경고. 여러 날 결석도 경고.
- **법정감염병**: 의사 소견서에 적힌 기간 밖의 날짜가 있으면 경고. 소견서 기간 미입력도 경고.
- **체험학습**
  - 신청서: 실시 2일 전까지 (기본 **수업일 기준** — 결재는 수업일에만 가능하므로)
  - 보고서: 실시 후 7일 이내 (기본 **달력 날짜 기준**)
  - 위 두 기준은 설정에서 수업일/달력 중 선택 가능
  - 국외: 1회 연속 10일 이내 (수업일 기준)
  - 국내+국외 연간(학년도) 총 20일
  - 반일(0.5일) 단위 가능: 하루짜리 오전은 인정지각, 오후는 인정조퇴. 여러 날이면 첫날 오후부터(첫날 인정조퇴)·마지막 날 오전까지(마지막 날 인정지각) → 1.5일, 2.5일 등. 기록 하나로 묶고 서류도 한 벌.
  - 보호자 미동반 교외체험학습 불가
  - **사후 신청 불가**: 기한 지나 받은 신청서, 신청서 없이 실시한 경우 "미인정 처리 대상" 경고
  - 결재 여부는 앱에서 관리하지 않음
- **공통**: 결석 기록이 같은 학생의 다른 기록과 날짜가 겹치면 경고. 결석 기간에 수업일이 없으면 경고.

## 화면

1. **오늘 (첫 화면, 모바일 우선)**: 날짜(◀▶ 이동)와 아래 네 가지만 보인다.
   - **오늘 출결 현황**: "1. 김철수 : 질병결석 (감기)" 목록, 복사 버튼. 줄을 누르면 그 학생 기록. 경고가 있으면 ⚠ 표시.
   - **출결 입력**: 누르면 학생 명단 → 학생 선택 → 상황·종류(·사유)·상세 사유 → 저장 후 명단으로 돌아와 이어서 입력.
   - **체험학습 신청 접수**: 학생·기간·국내/국외·보호자 동반. 하루면 종일/오전/오후, 여러 날이면 첫날 종일/오후부터·마지막 날 종일/오전까지 (1.5일, 2.5일 등). 남은 연간 일수와 경고를 저장 전에 표시. 신청서는 접수일로 받음 처리.
   - **받아야 할 서류**: 기한 지난 것 먼저, "받음" 버튼. 체험학습 보고서는 접수 때부터 표시.
   - 모바일에서는 탭이 화면 아래에 있고 입력창은 전체 화면으로 열린다.
2. **현황판**: 학생별로 상황×종류 표(결석은 일수, 나머지는 횟수), 총결석일수, 출석인정 결석일수, 체험학습 사용 일수(학년도 누적/20), 누락서류 수, 경고 수. 학년도·월 단위로 보기, CSV(엑셀) 내보내기. 학생을 누르면 해당 학생의 기록 목록.
3. **출결 기록**: 학생·월·누락·경고로 거르는 기록 목록. 서류 칩을 눌러 바로 받음 처리. 새 기록은 여러 학생에게 한 번에 입력 가능.
4. **달력**: 월 달력에 날짜별 출결 표시. 날짜를 눌러 출결 추가, 재량휴업일·공휴일 지정/해제 (갑자기 생기는 재량휴업일 대응).
5. **설정**: 학급명, 학생 명단(엑셀 붙여넣기), 휴일 관리, 체험학습 규정 수치, 백업.

## 집계 기준

- 학년도: 3월 1일 ~ 다음 해 2월 말
- 총결석일수 = 질병 + 미인정 + 기타 결석일수 (출석인정 제외)
- 출석인정 결석일수는 따로 표시
- 출결 통계는 **오늘까지만** 센다 (미리 접수한 체험학습 등 예정 기록 제외)
- 체험학습 일수는 사용(오늘까지)과 예정(내일부터)을 나눠 "5+3/20"처럼 표시
- 지각·조퇴·결과의 결석 환산은 하지 않음

## 기술 구성

- Vite + React + TypeScript, 서버 없는 정적 웹앱
- 저장: IndexedDB (`attendance-app` DB), `navigator.storage.persist()` 요청
- 도메인 로직(`src/domain`)은 UI와 분리하고 Vitest 로 테스트

```
src/
  domain/
    types.ts      데이터 모델
    calendar.ts   날짜·수업일 계산
    rules.ts      필요서류, 일수 계산, 규칙 경고
    stats.ts      현황판 집계
  storage/db.ts   IndexedDB 저장, 백업
  store.tsx       앱 상태
  components/     화면
```

## 미정 / 추후 검토

- 공휴일: 2026·2027년 관공서 공휴일(대체공휴일, 노동절·제헌절 포함)을 기본으로 넣는다 (`src/domain/publicHolidays.ts`). 2028년 이후와 임시공휴일은 교사가 직접 등록하거나 목록을 갱신한다.
- 결석계 제출 기한 규정이 정해지면 기한 경고 추가.

## 나이스 자동 입력 연결

- 지각은 "몇 교시까지 빠졌는지"(조회만 포함), 조퇴는 "몇 교시부터 빠졌는지"를 필수로 입력한다. 체험학습 반일도 같다.
- 「출결 기록 → 나이스 파일」: 기간을 골라 날짜별 한 줄짜리 파일(`attendance_neis_*.json`)을 만든다.
  결과와 교시 없는 지각·조퇴는 자동 입력을 못 하므로 따로 표시한다.
- 나이스 입력은 [YeoBBun/neis-automation-kit](https://github.com/YeoBBun/neis-automation-kit)
  (방배중 안정연 선생님 키트의 포크)의 `app_to_neis.py` 가 다운로드 폴더의 파일을 읽어 키트의 `main.py` 로 넣는다.
  키트의 구글 캘린더 읽기만 바꿔 끼우므로 원본 코드는 그대로이고, 구글 연동이 필요 없다. `/앱출결` 스킬로 실행.
- 나이스는 PC에서만 접속되므로 **PC 웹(학교 PC 크롬)을 기본 사용 환경**으로 본다. 앱 데이터와 다운로드 파일, 키트가 한 PC에 있으면 파일을 옮길 필요가 없다.

## 교내 출결 기준표 반영 (v3)

- 질병결석: 2일 이하 → 결석계만 (보호자 확인은 결석계 담임확인란에 하므로 따로 체크하지 않음), 진료확인서는 선택. 3일 이상이거나 **시험 기간**(설정)에 걸치면 진료확인서·처방전 등 필수.
- 기타: 근거 서류 필수. 학교장이 인정한 부득이한 사유만 해당한다는 안내를 입력 화면에 표시.
- 미인정: 출력물 학생 서명 확인.
- 체험학습: 국내·국외 모두 1회 연속 10일 이내, 연간 20일. 초과분은 미인정결석 대상이라고 경고. 서류는 신청서·보고서 (근거자료(사진·항공권·입장권 등)는 보고서에 첨부하므로 따로 체크하지 않음).
- 경조사: 종류를 고르면 인정 일수(결혼 1, 입양 20, 부모·(외)조부모 사망 5, (외)증조부모 사망 3, 부모의 형제자매 사망 3)를 넘을 때 경고. 일수는 체험학습과 같이 수업일 기준으로 센다 (2026-10 확인).
- 나이스 특기사항 대상(현황판): 질병·미인정 연속 10일 이상(기록이 나뉘어도 이어서 셈), 기타결석, 개근(질병·미인정·기타 기록이 없는 학생).
- 기록 삭제: 확인창 없이 바로 지우고 8초 동안 '되돌리기'.
- 이전 데이터는 불러올 때 서류 필수 여부를 기준표 값으로 맞춘다 (받은 상태는 유지).

- 생리: 결석·지각·조퇴·결과를 통틀어 무조건 달력 월 기준 월 1회 (2026-10 확인).

## 휴대폰 입력 → 학교 PC 자동 입력 (2026-10)

- 학교 업무망에서는 PC용 구글 드라이브 동기화가 막혀 있지만 크롬에서 드라이브 웹 다운로드는 된다.
- 휴대폰: 「나이스 파일 → 드라이브로 보내기」 (공유 창. 안드로이드 크롬이 .json 공유를 막아 같은 내용을 .txt 로 보냄)
- 학교 PC: 크롬에서 드라이브 웹을 열어 파일 다운로드 → 키트의 `app_to_neis.py --auto` 가 예약 시각(평일, 작업 스케줄러)에
  아직 넣지 않은 파일만 넣고 결과를 기록한다. 마감은 선생님이 나이스에서 확인 후.

## 휴대폰 ↔ PC 동기화 (깃허브 비공개 저장소, 2026-10)

- 휴대폰 「나이스 반영」 → 학교 PC 자동 입력은 만들었다가 쓰지 않기로 하고 뺐다 (PC 가 켜져 있으면 PC 에서 하면 되므로).
  대신 출결 앱 데이터 전체를 휴대폰과 PC 가 서로 맞춘다.
- 설정 → 휴대폰 ↔ PC 동기화: 저장소(YeoBBun/school-attendance-sync), 토큰(그 저장소만, Contents 읽기·쓰기), 잠금 비밀번호.
  이 기기의 localStorage 에만 저장하고 백업 파일에는 넣지 않는다. 기기마다 토큰을 따로 만든다.
- 저장소의 sync/state.json 하나에 앱 데이터 전체를 gzip → PBKDF2-SHA256(210,000회) → AES-256-GCM 으로 잠가 둔다.
- 이 기기에서 고친 항목에 updatedAt 을, 지운 항목은 tombstones(120일 보관)에 지운 시각을 남긴다 (store 의 commit 에서 자동).
- 맞추기: 받아서 합치고(같은 항목은 나중에 고친 쪽, 지운 시각이 더 나중이면 지운 채로) 달라졌으면 올린다.
  그 사이 다른 기기가 올렸으면(409/422) 다시 받아서 합친다. 두 기기에서 따로 등록한 같은 학생(번호·이름 같음)은 하나로 합치고 기록을 옮긴다.
- 언제: 앱을 열 때, 다시 볼 때, 고친 뒤 4초, 켜 둔 동안 1분마다. 머리글에 「✓ 동기화됨 / ⚠ 동기화 안 됨」.
- 백업 알림 시각(lastBackupAt)은 기기마다 따로.
- 나이스 입력은 PC 에서 키트로 (다운로드 폴더 방식 그대로).

## 안드로이드 홈 화면 위젯: 받을 서류 (2026-10)

- 웹앱은 홈 화면 위젯을 만들 수 없어서, 위젯만 하는 작은 안드로이드 앱(android-widget/)을 따로 둔다. 설치는 android-widget/README.md.
- 출결 앱이 동기화할 때마다 '받아야 할 서류' 요약(누구·무슨 서류·언제 출결·기한)을 같은 잠금 비밀번호로 잠가 sync/pending.json 에 올린다.
  내용이 지난번에 이 기기가 올린 것과 같으면 건너뛴다. 실패해도 출결 동기화는 그대로 되고 다음 동기화 때 다시 올린다.
- 서류 규칙은 웹앱에만 둔다 — 위젯은 요약을 풀어서 보여주기만 한다 (src/domain/pending.ts 의 widgetSummary).
  오늘 날짜에 따라 바뀌는 것(기한 지남 → 빨갛게 위로, 체험학습 '다녀온 후')은 위젯이 계산한다. 그래서 출결이 그대로면 요약도 그대로다.
- 위젯은 1시간마다(인터넷 될 때) 받고, 새로고침 버튼으로 바로 받는다. 파일 sha 가 같으면 풀지 않는다.
- 휴대폰에서는 위젯 앱이 출결 앱(웹)을 앱 화면(WebView)으로 띄운다 — 브라우저·크롬 설치 여부와 상관없이 앱으로 열리게.
  WebView 에서 안 되는 파일 저장·공유·선택은 앱이 맡는다 (src/platform/android.ts ↔ WebAppActivity).
- 위젯은 출결 앱의 동기화 설정을 그대로 쓴다: 출결 앱이 동기화할 때마다 설정을 앱에 넘긴다(setSyncConfig).
  처음엔 위젯용 읽기 전용 토큰을 따로 두었지만, 쓰기 토큰도 같은 앱 저장 공간에 있게 되어 나눠 둘 이득이 없어 합쳤다.

## 학생 한눈에 보기 · 관찰·상담 기록 (2026-10, 담임 올인원 1단계)

- 메뉴는 셋만: **오늘 / 학생 / 더보기**. 출결 기록·출결 통계·설정은 «더보기» 안에 둔다 (예전 주소 #records, #stats, #settings 는 그대로 열린다).
- **학생 탭**: 명단 → 학생을 누르면 `#students/학생id`. 그 학생에 대해 적은 것(출결, 관찰·상담 기록)을 학년도 단위로 한 화면에 모은다.
  - 요약 카드: 출결(결석일수·지각·조퇴·결과·받을 서류), 관찰·학생상담·학부모상담 건수, 남은 할 일. 카드를 누르면 그것만 거른다.
  - 아래 목록은 최근 것부터. 같은 날이면 출결이 먼저. 내용 검색.
  - [기록 남기기] [출결 입력] 두 버튼만 크게.
- **기록(notes)**: 유형(관찰·학생상담·학부모상담)과 내용만 보이고, 날짜·할 일(후속 조치)·같이 있던 학생은 «더 적기» 안에.
  학부모상담은 누구와(어머니 등)·어떻게(대면·전화·문자)를 더 적는다.
  같이 있던 학생을 고르면 그 학생 페이지에도 같은 기록이 보인다 (`studentIds` 여러 명).
- 기록 삭제도 출결처럼 확인창 없이 지우고 8초 동안 '되돌리기'.
- 데이터: AppState v6 에 `notes` 추가. 동기화 tombstone 키는 `n:기록id`. 이전 파일(v1~v5)은 notes 없이 읽힌다.
  두 기기에서 따로 등록한 같은 학생을 합칠 때 기록의 학생도 옮긴다. 학생을 지우면 그 학생만 기록에서 빼고, 남은 학생이 없는 기록은 지운다.
- 주의: v6 데이터는 v5 앱에서 열리지 않는다. 휴대폰·PC 모두 새 버전으로 열어야 동기화된다.

## 학급관리 2단계: 학급 모듈 · 구글 연동 (2026-10)

원칙: 화면은 단순하게 — 한 화면에 한 가지 일, 꼭 필요한 칸만 먼저, 확인창 대신 되돌리기, 쉬운 말.

- **«더보기» 묶음**: 학급(제출물 체크·명심보감 필사·사안 관리·자리 배치) / 나이스·생기부(누가기록·행발 쓰기) / 출결(기록·통계) / 설정.
- **오늘 «챙길 일»**: 결과를 안 적은 상담(날짜 지남), 14일 안의 상담 일정, 끝나지 않은 할 일(체크하면 끝), 덜 걷힌 제출물(마감 가까운 순), 진행 중 사안, 필사 덜 낸 학생. [+ 상담 일정]으로 바로 잡기.
- **제출물 체크** (`checklists`): 이름·마감만 적으면 학생 칸이 생긴다. 누르면 냄(날짜) / 「누르면 면제」 모드. 안 낸 학생 복사, 구글 시트로, [다 걷었어요]로 치우기.
- **명심보감 필사** (`pilsa`): school-myungsim 의 규칙 그대로 (처음 N장, 부여할 때마다 +M장). 칸 하나가 한 장, 빈 칸을 누르면 낸 것(앞에서부터), 채운 칸은 마지막 것 취소.
  예전 필사 기록(아티팩트)은 옮겨 오지 않았다.
- **상담 일정**: 학부모상담에 「상담 일정 잡기」(날짜·시각). `planned` 인 동안은 건수에 안 세고, 내용을 적어 「한 상담 적기」로 저장하면 끝난 상담.
- **나이스 누가기록**: 안 넣은 관찰·상담 기록을 학생별로 [복사] → 나이스 → [넣음] 체크(`neisDone`). 키트용 파일 `class-app/nuga-v1` 도 만든다.
  키트 쪽 자동 입력 스크립트는 아직 없다 — 나이스 누가기록 화면을 실제로 보면서 만들어야 한다.
- **행발 쓰기** (`behavior`, id `학년도:학생id`): 1년 기록(관찰·상담·사안, 출결·필사 요약)을 보며 초안. 나이스 바이트(한글 3, 영문·숫자·띄어쓰기 1, 줄바꿈 2), 한도 설정(기본 1500), 다 썼어요 표시.
- **자리 배치** (`seatPlans`, 조건은 `settings.seating`): 줄×칸·짝. 섞기는 400번 섞어 벌점이 가장 적은 배치(앞자리 학생은 앞 2줄, 떨어뜨릴 두 학생은 옆·앞뒤 금지 — 어기면 100점, 지난번 짝 다시 짝 — 1점). 빈자리는 뒤로.
  두 자리를 차례로 누르면 바꾸기. 저장하면 이력. 인쇄: 게시용(학생 시점, 칠판 위) / 교탁용(교사 시점, 위아래·좌우 반전, 칠판 아래).
- **학생 페이지**: 출결·관찰·학생상담·학부모상담·필사·사안 카드, 상담 일정·할 일·안 낸 제출물 안내, 모든 기록을 한 목록에. [가림]은 상담·사안 내용을 흐리게(이 기기에 기억), [인쇄]는 한 장 요약.

### 구글 연동

- 로그인 하나(Google Identity Services, 서버 없음)로 드라이브·캘린더·시트. 권한은 `drive.file`(앱이 만든 파일·폴더만) + `calendar.app.created`(앱이 만든 캘린더만).
  클라이언트 ID 는 수업관리(school-timetable)와 같은 것을 쓴다(`src/google/config.ts`) — 승인된 자바스크립트 원본에 배포 주소가 있어야 한다.
- 로그인은 1시간쯤 뒤 끝난다(서버가 없어 새로 받을 수 없다). 끝나면 설정의 [구글 다시 연결].
- **다른 기기와 맞추기 (드라이브)**: 내 드라이브 '학급관리' 폴더의 `class-state.json`. 깃허브 때와 같은 잠금(AES-GCM)·합치기. 드라이브는 조건부 쓰기가 없어 쓰기 직전에 버전을 다시 보고, 바뀌었으면 다시 받아 합친다.
  깃허브 방식은 설정의 「고급」으로 남겼다 (휴대폰 위젯은 깃허브 방식에서만).
- **캘린더**: 켜면 '학급관리' 캘린더를 만들고, 상담 일정(시각 있으면 30분, 없으면 하루 종일)과 제출 마감(하루 종일)을 넣는다. 캘린더에는 이름·일시만, 상담 내용은 넣지 않는다.
  넣은 일정은 `calendarLinks`(항목 키 → 일정 id·내용 요약)로 기억해 바뀐 것만 고치고, 없어진 항목의 일정은 지운다. 동기화를 켰으면 받은 뒤에 맞춘다(같은 일정을 두 기기가 두 번 넣지 않게).
- **시트**: 출결 통계·제출물에서 [구글 시트로] → 드라이브 '학급관리' 폴더에 시트를 만들고 [시트 열기].

## 메뉴·일정·학생 기록 다듬기 (2026-10)

- 메뉴는 **오늘 / 더보기 / 설정**. 더보기는 화면을 넘기지 않고 작은 창(휴대폰은 아래에서 올라오는 판)으로 연다 — 어느 화면에서든 한 번에 이동.
- 오늘 화면 명단 칸에 [체험학습 접수]. «챙길 일» 은 «처리할 일» 로, 상담 일정 추가는 더보기 → 일정에서.
- **일정** (`events`, 동기화 키 `e:`): 학부모 상담(학생을 골라 상담 일정 = 관찰·상담 기록의 planned), 학급 행사, 기타. 제출 마감도 같이 보인다. 다가오는 것만 펼치고 지난 것은 접는다.
  구글 캘린더를 켜면 학급 일정도 들어간다(시각 있으면 1시간). 처리할 일에 14일 안의 학급 일정.

## 처리 예정 묶음, 기록 작성 시각 (2026-10-30)

- 오늘 화면의 «처리할 일»을 «처리 예정»으로. 학생별이 아니라 종류별 묶음: 출결 서류 · 일정(상담·학급 일정) · 제출물 · 할 일(상담 결과 적기·후속 조치) · 필사. 묶는 규칙은 src/domain/plan.ts 하나를 웹과 위젯이 같이 쓴다.
- 날짜가 있는 줄(일정, 서류·제출물 기한)에는 남은 날 D-0 / D-3 / 지나면 D+2.
- 위젯 요약(sync/pending.json)은 같은 형식 이름에 sections 를 더했다. 예전 위젯 앱은 items(받을 서류)만 읽으므로 그대로 동작하고, 새 위젯은 묶음을 읽는다. D-day·지난 일정 감추기는 위젯이 오늘 날짜로 계산한다.
- 관찰·상담 기록에 작성 시각(writtenAt)과 수정 시각(editedAt)을 남긴다. 내용이나 날짜를 고치면 고치기 전 판을 history 에 쌓아, 처음 적은 내용과 시각이 지워지지 않는다. 학생 기록 화면, 고치기 창, 인쇄에 보인다.
- 시각은 그 기기 시계 기준이고, 기록을 지우면 이력도 함께 지워진다 (공증된 시각은 아니다).
